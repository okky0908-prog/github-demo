# 要件定義書：Trello風タスク管理アプリ

## 1. 概要

個人利用を目的とした、Trello風のシンプルなタスク管理Webアプリケーション。
スクール課題として開発する。

## 2. 背景・目的

- 本プロジェクトはスクールの課題として取り組むものであり、特定の業務課題やビジネス上の目的があるわけではない
- 主目的は学習：要件定義〜設計〜実装という開発の一連の流れを一人で経験し、身につけること
- 副次的な狙いとして、実際に自分の日々のタスク管理に使えるものを作ることで、成果物としての実用性・学習の定着度を高める

## 3. 想定利用者

- 開発者本人のみ（1ユーザー）
- ログイン・認証機能は不要

## 4. スコープ

### 4.1 今回実装する範囲（MVP）

- ボード・リスト・カードによるタスク管理
- カードのドラッグ&ドロップ（リスト間移動、リスト内並び替え）
- バックエンドAPI・データベースによるデータ永続化（ブラウザを閉じてもデータが残る）

### 4.2 将来的に追加したい範囲（今回は対象外）

- ラベル・タグ
- コメント機能
- 検索・フィルタ
- 複数ボードの切り替え
- ログイン・複数ユーザー対応

### 4.3 明確に対象外とするもの

- 担当者（アサイン）機能
- 他ユーザーとのデータ共有・同期

## 5. 機能要件

ボード・リスト・カードの3階層でタスクを管理する。ボードは1つのみ、リストとカードはそれぞれ作成・編集・削除・並び替えに対応する。

→ 詳細は [機能要件](./features.md) を参照

## 6. 画面仕様・画面遷移・ユースケース

単一ページ構成（SPA）とし、ボード画面とカード編集モーダルのみで完結する。リスト名編集やカード追加はインライン入力とする。

→ 詳細は [画面仕様・画面遷移・ユースケース](./screens.md) を参照

## 7. 非機能要件

性能・可用性・セキュリティ・保守性・ユーザビリティ・互換性・データ永続性の観点で、個人のローカル環境での利用を前提とした要件を定義する。

→ 詳細は [非機能要件](./non-functional-requirements.md) を参照

## 8. データ構造・ER図

Board・List・Cardの1:N構造とする。将来の複数ボード対応を見据え、Boardを起点としたデータ構造とする。

→ 詳細は [データ構造・ER図](./database.md) を参照

## 9. 技術スタック

フロントエンドはReact + TypeScript + Vite、ドラッグ&ドロップはdnd-kitを採用。バックエンドはJava + Spring Boot、DBはPostgreSQL（Spring Data JPA + Flyway）を採用する。

→ 詳細は [技術スタック](./tech-stack.md) を参照
